# BandWagon 1.0.0 Release Candidate 1

This candidate freezes the intended v1 product contract. It is not a general-availability declaration; production provider approvals, restore evidence, tenant setup, and human safety drills remain required by the [v1 launch checklist](../operations/V1-LAUNCH-CHECKLIST.md).

## Candidate scope

- Complete parent/guardian, managed-student, driver, ride, reminder, and verified-pickup workflows.
- Organization-scoped Google and Microsoft read-only calendar synchronization, conflict controls, and organizer-created manual events.
- Organization administration, tenant onboarding, privacy export/deletion, exact-location retention, and audited support operations.
- Credential vault, organization-defined driver eligibility, Emergency Assist, and safety maintenance.
- Push-first notification routing with email/SMS fallback and provider cost visibility.
- PWA install/offline shell, shared keyboard/accessibility safeguards, error monitoring, and load smoke gate.
- Staged data-key rotation, stable lookup hashes, backup/restore verification tooling, and production readiness profiles.
- AI disabled by default, organization opt-in, bounded inputs/timeouts, approved model aliases, budget reservations, audited fallback, and deterministic core workflows.

## Event publishing policy

For v1, owners, administrators, and managers may create and edit manual events. Ordinary members cannot publish events. Member-created event proposals are deferred until an organization-controlled moderation policy is designed and tested.

## Launch blockers outside the candidate code

- Twilio production approval and live opt-in/STOP/HELP/fallback verification.
- Google OAuth approval and live read-only calendar verification.
- Production backup restored and verified in an isolated environment.
- FloMoGo tenant configuration, named administrators, calendar selection, driver requirements, and removal of seed/test data.
- Complete human regression, accessibility/mobile checks, and pickup/emergency safety drills.
- If AI is enabled, production LiteLLM hard budget plus provider privacy/logging evidence. AI may remain disabled for v1.

## Release procedure

1. Require a green release-branch CI run.
2. Run `npm run release:check-env:flomogo` against the production secret set.
3. Deploy the exact candidate commit to staging and complete the launch checklist.
4. Record all sign-offs and the rollback decision owner.
5. Freeze changes, tag `v1.0.0`, deploy that exact tag, and run production smoke tests.
6. Schedule the seven-day review and 30-day retrospective.

Do not change `apps/web/package.json` to `1.0.0` or tag the release until every launch gate is green.
