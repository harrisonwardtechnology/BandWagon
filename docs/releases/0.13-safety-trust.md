# BandWagon 0.13 - Safety & Trust

0.13 makes safety, driver trust, document privacy, and AI-assisted administration first-class BandWagon capabilities.

## Release scope

### Age / guardian controls
- Direct account signup collects month + year rather than full date of birth.
- Direct accounts require age 13+.
- Under-13 users are directed to a parent-managed dependent profile.
- Ages 13-17 remain identified as minors for guardian and organization policy.

### Emergency Assist
- Authenticated Safety page for active rides.
- One-tap `tel:911` action; BandWagon does not represent itself as an emergency dispatch service.
- `I Need Help` / safety-circle alerts.
- Push + immediate SMS/RCS + email when available through the critical notification policy.
- Exact device coordinates, when volunteered by the user, are encrypted before database storage.
- Safety alert history and resolution audit.

### Driver Credential Vault
- Private IONOS S3-compatible object storage.
- Pre-signed upload and temporary view URLs only.
- Driver license, insurance, volunteer approval, and supporting document types.
- PDF/JPEG/PNG/WebP, maximum 10 MB.
- Document access audit events.
- Documents are person-level so one credential can support multiple organization reviews.

### Organization Driver Requirements
Each organization controls:
- minimum driver age
- district-approved volunteer: Not Used / Display / Required
- driver license: Not Used / Optional / Required
- insurance: Not Used / Optional / Required
- organization manual approval
- suspend on expired credentials
- AI fact extraction enabled / disabled

AI never approves a driver. Organization administrators make approval decisions.

Driver eligibility is enforced at the database boundary for ride offers and new rides. Ineligible driver match suggestions are discarded.

### AI Gateway
- LiteLLM Proxy is the single gateway for normal LLM traffic.
- `bandwagon-fast`, `bandwagon-balanced`, and `bandwagon-deep` model aliases isolate the application from provider/model changes.
- Google Document AI remains a specialized direct path for configured identity document processors.
- Insurance image extraction uses LiteLLM.
- Driver license processing uses the configured Google Document AI processor.
- AI output is treated as untrusted extracted data and remains pending human review.
- `ai_jobs` and `ai_usage_daily` provide BandWagon-level purpose/cost accounting.

### Safety & Trust Operations Dashboard
Organization administrators can see:
- rides today / month
- opted-in and eligible drivers
- pending credential reviews
- credentials expiring within 30 days
- open / monthly safety alerts
- AI jobs and spend by purpose/model
- estimated ride operating cost
- estimated driver validation cost
- community support and estimated cost coverage

### Community Support
Public support messaging now includes both planning estimates:
- approximately `$0.25` per coordinated ride
- approximately `$0.50` per driver validation

Impact examples are estimates and contributions are not represented as restricted or tax-deductible donations.

## Required / recommended environment variables

### IONOS S3
```text
S3_ENDPOINT=<IONOS S3 endpoint>
S3_REGION=<bucket region>
S3_ACCESS_KEY_ID=<secret>
S3_SECRET_ACCESS_KEY=<secret>
S3_PRIVATE_BUCKET=<private document bucket>
S3_PUBLIC_BUCKET=<public asset bucket>
S3_FORCE_PATH_STYLE=false
```

The private bucket must remain non-public. Configure bucket CORS to permit browser `PUT` uploads from approved BandWagon application origins. Prefer exact production origins; add tenant hostnames as they are activated.

### LiteLLM
```text
LITELLM_BASE_URL=http://<private-coolify-service>:4000
LITELLM_API_KEY=<BandWagon virtual key>
AI_FAST_MODEL=bandwagon-fast
AI_BALANCED_MODEL=bandwagon-balanced
AI_DEEP_MODEL=bandwagon-deep
```

Provider API keys belong in LiteLLM, not BandWagon.

### Google Document AI
```text
GOOGLE_DOCUMENT_AI_SERVICE_ACCOUNT_JSON=<service account JSON secret>
GOOGLE_DOCUMENT_AI_PROCESSOR_NAME=projects/<project>/locations/<location>/processors/<processor>
GOOGLE_DOCUMENT_AI_ENDPOINT=https://documentai.googleapis.com
GOOGLE_DOCUMENT_AI_COST_USD_PER_DOCUMENT=0.10
```

Grant the service account only the permissions required to invoke the configured processor.

### Safety maintenance
```text
SAFETY_CRON_SECRET=<random long secret>
```

Call `POST /api/cron/safety-maintenance` daily with `Authorization: Bearer <SAFETY_CRON_SECRET>` to:
- mark expired credentials expired
- send 30 / 14 / 7 / 1 / 0 day reminders

## Deployment

After merge and successful Coolify deployment:

```bash
npm run db:migrate
```

Expected new migrations: 018 through 023.

Do not delete or rotate existing `DATA_ENCRYPTION_KEY` or `AUTH_SECRET` during this deployment.

## Smoke test

1. Create a new account with month/year and verify under-13 direct signup is rejected.
2. Confirm a 13-17 signup remains a minor account.
3. Upload a test credential to the private bucket and confirm no public object URL exists.
4. Open the credential through BandWagon and verify the temporary URL expires.
5. Set an organization to require district volunteer + license + insurance.
6. Confirm an unverified driver is not eligible and cannot create a ride offer.
7. Submit credentials and approve each requirement as an organization admin.
8. Confirm the driver becomes eligible.
9. Trigger `I Need Help` on a test ride and verify safety-circle notifications.
10. Verify 911 opens the device dialer and BandWagon does not claim to contact 911 itself.
11. Run an insurance image extraction through LiteLLM and verify the result remains Pending Review.
12. Run the configured Google Document AI driver-license processor and verify unnecessary identifiers are not retained in BandWagon metadata.
13. Review AI cost/purpose totals in `/admin/operations`.
14. Verify `/support` shows both ride and driver-validation impact estimates.
