# BandWagon 0.16 - Managed Student Accounts

This v1-readiness slice lets a guardian authorize a managed student to sign in without creating a second person or household profile.

## What Changed

- Household managers can configure one login email for each managed student.
- The student's first OTP verification claims the existing managed profile and creates its user account.
- A student login requires both enabled guardian-managed access and at least one active platform-use consent.
- Disabling access or revoking the final active guardian consent immediately revokes active student sessions.
- Changing the authorized email prevents the previous email from authenticating the managed account.
- Email ownership, access changes, and account claims are recorded without writing the email address into audit metadata.
- Existing direct accounts remain compatible unless managed-student access has explicitly been configured.

## Migration

Apply `050_managed_student_accounts.sql`, then run:

```bash
npm run db:migrate
npm run db:verify
```

## Smoke Test

1. Sign in as a household manager and open `/app/household`.
2. Add a managed student and confirm guardian consent is active.
3. Enter a student email and enable sign-in.
4. In a private browser, choose **Sign in**, request a code for that email, and verify it.
5. Confirm the student lands in the existing profile and household.
6. Disable student sign-in and confirm the active student session no longer authenticates.
7. Re-enable sign-in, then revoke the final active guardian consent and confirm access is denied again.

## Exit Criteria

- Policy tests, TypeScript, production build, migrations, and schema verification pass.
- A managed profile is claimed without creating a duplicate person or household.
- Disabled access and final-consent revocation invalidate active sessions.
