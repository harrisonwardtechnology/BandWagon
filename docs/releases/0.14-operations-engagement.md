# BandWagon 0.14 - Operations & Engagement

0.14 turns the core ride engine into a polished day-to-day operating product for riders, guardians, drivers, and organization administrators.

## Release Scope

### Verified Pickup Handshake
- One-time pickup QR / token flow.
- Four-digit fallback code.
- Shared visual phrase such as `Blue Cow` with icon + color + words.
- Driver and rider / guardian both confirm.
- Short-lived and replay-resistant.
- Organization modes: Off / Optional / Recommended / Required.
- Guardian can independently require verified pickup for a student.
- Required verification is enforced before `Picked Up`.
- Successful verification can advance `Arrived -> Picked Up` automatically.

### Ride Engagement
- 24-hour and 1-hour reminders.
- Deduplication prevents repeated reminders.
- Push-first routing to reduce messaging cost.
- Notification preferences remain user-controlled except where critical safety delivery is required.

### AI Event Intake
- Admin can paste an email, announcement, or other event text.
- AI proposes structured event fields.
- Admin review is mandatory before publishing.
- Organization AI opt-in is enforced before any provider call.

### Organization AI Controls
AI is off by default.

Organizations can separately opt into:
- driver document review
- AI event intake
- match explanations
- admin copilot
- safety summaries

Turning AI off removes automation, not core BandWagon functionality.

### RouteAssist
Drivers can opt in per organization and define both:
- maximum added time
- maximum route deviation percentage

Suggested default when enabled:
- 10 minutes
- 10 percent

BandWagon uses whichever limit is reached first.

RouteAssist:
- evaluates open ride requests against trips the driver is already taking
- checks capacity, direction, organization, event compatibility, and driver eligibility
- uses Google Maps Routes when configured
- falls back to a conservative generalized-location estimate
- never exposes the driver's full route to riders
- stores recommendations with Fit score and reasons
- supports Offer Ride / Dismiss actions
- can notify drivers about strong matches

### Routing Privacy / Cost Controls
- Route cache keys are hashed.
- Full route traces are not persisted.
- Repeated comparisons can use cache.
- Per-organization routing usage and estimated cost are tracked.

### Ride Coverage / Outcomes
Admin operations now surfaces:
- open ride requests
- seats still needing coverage
- requests open more than two hours
- monthly match rate
- completed rides
- cancellations
- no-shows
- RouteAssist recommendations / offers

No-show events retain actor, timestamp, and optional note.

### Notification Delivery Health
Organization administrators can review:
- Push / Email / SMS / RCS delivery counts
- success and failure status
- recent failed / undelivered notifications
- estimated messaging cost
- SMS / RCS volume

Routine traffic remains Push-first. Critical safety flows retain their stronger delivery path.

### Community Support
Support messaging includes planning impact examples:
- about $0.25 per coordinated ride
- about $0.50 per driver validation
- $1 is approximately 4 rides or 2 driver validations
- $5 is approximately 20 rides or 10 driver validations
- $25 is approximately 100 rides or 50 driver validations

These are planning estimates, not restricted-fund or tax-deductible donation claims.

## Environment Variables

### Google Maps Routes

```text
GOOGLE_MAPS_ROUTES_API_KEY=<server-side Routes API key>
GOOGLE_ROUTES_ESTIMATED_COST_USD_PER_CALL=<planning estimate per provider call>
```

Restrict the API key to the required Google Maps Routes service and the intended production environment where possible.

If the Routes API is unavailable, RouteAssist falls back to the internal conservative estimator.

### Existing 0.13 AI / Safety Configuration
0.14 continues to use the 0.13 LiteLLM, Document AI, S3, and Safety settings. Do not remove or rotate working `AUTH_SECRET`, `DATA_ENCRYPTION_KEY`, S3, LiteLLM, or Google Document AI settings as part of this release.

## Cron / Scheduled Work

Continue the 0.13 safety-maintenance job.

Add the ride-reminder job on a regular schedule suitable for 24-hour and 1-hour reminders:

```text
POST /api/cron/ride-reminders
```

Use the configured server-side authorization secret expected by the endpoint. Do not expose cron credentials in browser code.

## Smoke Test

1. Create an open ride request and accept a driver offer.
2. Advance driver to `On My Way` then `Arrived`.
3. Start pickup verification and confirm QR / fallback-code workflow.
4. Verify both screens show the same phrase / color / icon.
5. Confirm a required pickup cannot be manually advanced without verification.
6. Complete both sides of the handshake and confirm the ride advances to Picked Up.
7. Mark a ride complete.
8. Cancel a test ride and confirm cancellation reason is retained.
9. Report a test no-show and confirm actor / time / note are retained.
10. Enable RouteAssist for a driver at 10 minutes / 10 percent.
11. Confirm a plausible open request produces a Recommended Ride card.
12. Confirm the card shows added minutes, deviation percent, distance, Fit score, and Why This Match.
13. Confirm the recommendation does not expose the rider's identity before the normal disclosure boundary.
14. Confirm Offer Ride uses the normal ride-offer workflow.
15. Configure `GOOGLE_MAPS_ROUTES_API_KEY` and confirm a recommendation records `google_routes`.
16. Temporarily remove / invalidate the key and confirm estimator fallback still works.
17. Verify repeated route comparisons produce cache hits.
18. Review routing usage / cost in the admin dashboard.
19. Verify admin coverage metrics for open requests, seats, match rate, cancellations, and no-shows.
20. Verify Notification Delivery Health shows Push / Email / SMS / RCS summaries and recent failures.
21. Verify routine reminder traffic remains Push-first and does not unexpectedly generate SMS.
22. Enable an organization AI feature and confirm the permitted action works.
23. Disable that feature and confirm the backend rejects the AI request while the manual workflow continues to work.
24. Paste an event announcement into AI Event Intake and confirm nothing publishes until an admin approves it.
25. Verify Support shows ride and driver-validation impact examples.

## Release Exit Criteria

- All migrations 024-031 apply cleanly to a production-like database.
- GitHub TypeScript check passes.
- GitHub production Next.js build passes.
- No tenant-scope regression is found.
- No exact driver route is exposed to riders or written to normal application logs.
- Required pickup verification cannot be bypassed through the ordinary ride-status API.
- Critical safety notifications remain stronger than ordinary user preference suppression.
- PR is only marked Ready after the smoke-test blockers are resolved.
