# BandWagon 0.15 - Privacy Production Slice

This 0.15 slice turns the privacy promises already described publicly into signed-in, self-service workflows with scheduled cleanup and operational verification.

## Release Scope

### User Data Export

- Signed-in users can download their data from `/app/settings/privacy`.
- The JSON export includes profile and contact data, household and guardian relationships, memberships, ride history, private locations, credential metadata, notification records, safety records, consents, and account activity.
- Exact address and phone values are decrypted only for the authenticated user's export response.
- Credential binaries are not embedded in the JSON file and remain available only through the private Credential Vault until deleted.
- Every export request and completion is recorded.

### Account Deletion

- Users schedule deletion by typing `DELETE MY ACCOUNT` exactly.
- The grace period defaults to seven days and can be configured from one to 30 days.
- A scheduled request can be cancelled until processing starts.
- Deletion is blocked while the user has active rides, unresolved ride requests or saved locations in use, sole organization ownership, sole guardian or household-manager duties, open safety alerts, or is the final platform owner.
- Direct sign-in and contact data is removed. Operational history is reduced to a pseudonymous `Deleted user` record where referential integrity, safety, fraud prevention, or audit history requires it.
- Support audit history is preserved with account references removed instead of cascading the history away.

### Credential Lifecycle

- A driver can delete an uploaded credential directly from the Credential Vault.
- Eligibility links, extracted AI data, filenames, metadata, and object-storage data are removed or queued for retry.
- Expired documents are purged after the longest active organization retention setting.
- Rejected and replaced documents follow the same retention window.
- Abandoned pending uploads are removed after 24 hours.

### Exact Location Lifecycle

- Completed and cancelled ride-request locations are automatically queued for exact-data deletion.
- The organization retention setting defaults to 30 days and supports one to 365 days.
- A location still used by an active request is not queued.
- Cleanup removes encrypted exact address and coordinate values plus pickup/drop-off notes tied to the expired locations. Generalized area data can remain for de-identified operations.

### Authentication Hardening

- Sign-in and account creation are explicit modes so the API does not reveal whether an email address or phone number already has an account.
- A sign-in attempt for an unknown identifier receives the same generic response and an unusable decoy challenge.
- OTP requests are throttled by both identifier and hashed source IP.
- OTP verification attempts are limited across challenges from the same hashed source IP.
- OTP delivery failures use the same outward response to avoid turning provider behavior into an enumeration signal.
- Production never returns debug OTP codes, even if a debug environment flag is accidentally left enabled.
- Sessions default to a 30-day absolute lifetime and a 14-day idle timeout. Session activity writes are coalesced to reduce database load.
- Authentication and session responses are private and non-cacheable; sign-out clears both user and support-mode cookies.
- Expired OTP challenges, orphan OTP destinations, and stale sessions are cleaned by privacy maintenance.

### Guardian Consent Controls

- Adding a managed student now records active, auditable guardian consent.
- Household managers can grant or revoke their consent from the Household screen.
- Guardians can independently require approval for every ride request and require the verified-pickup handshake.
- A minor cannot enter the ride-matching workflow unless at least one guardian has active platform-use consent.
- Changes are recorded in the audit log and existing privacy export/deletion workflows include or remove the consent records as appropriate.
- Organization owners can accept the current Terms of Use and Privacy Policy from `/admin/organization-policies`; each version, actor, timestamp, authority confirmation, and privacy-safe request fingerprint is retained in immutable organization history and the central audit log.


After deployment:

```bash
npm run db:migrate
npm run db:verify
```

The schema verifier checks the privacy tables, retention columns, exact-location trigger, and preservation rules for support audit foreign keys.

## Environment Variables

```text
ACCOUNT_DELETION_GRACE_DAYS=7
PRIVACY_MAINTENANCE_CRON_SECRET=<random secret, at least 32 characters recommended>
SESSION_TTL_DAYS=30
SESSION_IDLE_DAYS=14
```

`PRIVACY_MAINTENANCE_CRON_SECRET` falls back to `SAFETY_CRON_SECRET` when a separate secret is not configured.

## Scheduled Work

Call the endpoint at least hourly and no less frequently than every three hours:

```text
POST /api/cron/privacy-maintenance
Authorization: Bearer <PRIVACY_MAINTENANCE_CRON_SECRET>
```

The job:

- schedules expired, rejected, replaced, and abandoned credential cleanup
- retries private object deletion
- removes exact ride locations whose retention period has elapsed
- purges expired OTP challenges, redacts orphan OTP destinations, and revokes stale sessions
- processes due account deletions
- records a health heartbeat visible in Platform Health

## Smoke Test

1. Sign in and open `/app/settings/privacy`.
2. Download the JSON export and verify it contains only the signed-in user's private data.
3. Upload a test credential and delete it from the Credential Vault.
4. Confirm the document immediately disappears and its requirement returns to Not Submitted.
5. Create an active ride request and confirm account deletion is blocked.
6. Resolve the request, schedule deletion, then cancel it during the grace period.
7. Use a test account with no blockers and a one-day grace period to validate the maintenance job in staging.
8. Confirm sign-in no longer works after processing and the person is displayed only as `Deleted user` in retained operational history.
9. Complete a test ride, shorten the test organization's exact-location retention, run maintenance, and confirm exact address/ciphertext and pickup/drop-off notes are removed.
10. Verify support audit history remains present with deleted account references set to null.

## Exit Criteria

- TypeScript, policy tests, and production build pass.
- Migration `045` applies cleanly to PostGIS and a second migration run is a no-op.
- Database verification passes after migration.
- Export, deletion scheduling/cancellation, object deletion retry, and exact-location cleanup pass the staging smoke test.
- The privacy cron has a healthy heartbeat in Platform Health.
